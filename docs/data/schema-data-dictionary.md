# PostgreSQLスキーマ・データ定義書

本書は、投資判断プラットフォームで使用するPostgreSQLデータの意味、型、粒度、制約を定義します。

本書は列の**意味・由来・運用ルール**を担当します。型やNULL可否などの構造情報はAlembicから生成される
`schema-reference.md` が正本であり、本書の記載が食い違う場合は生成側を正とします。

スキーマ変更と文書生成の手順は開発ガイドを正本とします。CIは本書のテーブル・列とmigrationの
不足・余剰を検出します。

## 1. 共通データ規約

| 対象 | 規約 |
|---|---|
| 主キー | `BIGINT GENERATED BY DEFAULT AS IDENTITY`。代理キーは原則自動採番 |
| 日付 | `DATE` |
| 日時 | `TIMESTAMPTZ`、原則UTC。外部APIの日時を保持する場合は変換規則をETLに明記 |
| 時刻 | `TIME` |
| 真偽値 | `BOOLEAN` |
| 金額 | 通貨の最小単位を `BIGINT` で保持。財務データは原則「円」 |
| 株価・比率 | `DOUBLE PRECISION`。通貨は `investment_target.currency`、単位は列定義または取得元定義に従う |
| 株式数 | `BIGINT`、単位は株 |
| 欠損 | 不明・未提供は `NULL`。空文字やゼロで補完しない |
| 列挙値 | `CHECK` 制約に列挙された小文字・大文字をそのまま使用 |
| 作成・更新日時 | `created_at` / `updated_at`。`updated_at`は更新処理側で設定 |
| 外部キー | PostgreSQL制約として常時適用する |
| 冪等性 | 自然キーに `UNIQUE` を設定し、取込処理はUPSERTまたは同等の再実行可能な処理にする |

## 2. テーブル別データ由来一覧（生成主体）

ここでは各テーブルを**誰が生成するか**だけを定義します。外部データの採用元・代替候補・利用方針は
[取得元と利用方針](sources.md)、個別API項目の変換はETLコードとテストを正本とします。

| PostgreSQLテーブル | データ区分 | 主な生成主体 |
|---|---|---|
| `strategy` | ユーザー入力 | Strategy API |
| `theme` | ユーザー入力 | Theme API |
| `investment_target` | ユーザー入力・外部マスタ | Investment Target API、銘柄マスタ同期 |
| `data_source` | システム設定 | ETLの取得元登録処理 |
| `ingestion_run` | ETL内部生成 | バックフィル・差分更新ジョブ |
| `ingestion_error` | ETL内部生成 | 取得・正規化・検証・保存時のエラー記録 |
| `investment_target_identifier` | 外部API・システム変換 | 銘柄マスタ同期、識別子管理処理 |
| `theme_investment_target` | ユーザー入力 | Relationship API |

### データ区分

| 区分 | 意味 |
|---|---|
| 外部API | J-Quants、FRED、yfinance等から取得するデータ |
| ユーザー入力 | FastAPIまたは画面から登録・更新する業務データ |
| システム設定 | 取得元や固定キーなど、アプリケーション運用のために管理する定義 |
| ETL内部生成 | 取得処理の実行状況、エラー、ハッシュなど、データ来歴を記録する値 |
| 内部判定 | 取得値と設定済みルールからアプリケーションが計算する値。現行スキーマには保存しない |

## 3. テーブル一覧と粒度

| 区分 | テーブル | 1レコードの粒度 |
|---|---|---|

| マスタ | `investment_target` | 1内部銘柄・指数 |

| 列 | 定義 |

| `strategy_id` | 主キー |

| `strategy_name` | 表示名 |
| `description` | 説明 |
| `is_active` | 有効フラグ。既定値 `TRUE` |
| `created_at`, `updated_at` | 作成・更新日時 |

### `theme`

| 列 | 定義 |
| --- | --- |
| `theme_id` | 主キー |
| `theme_key` | システム内で不変のテーマキー。一意 |
| `theme_name` | 表示名 |
| `strategy_id` | `strategy`への参照。戦略分類の正本 |
| `description` | 投資テーマの説明 |
| `is_active` | 有効フラグ |
| `created_at`, `updated_at` | 作成・更新日時 |

### `investment_target`

| 列 | 定義 |
| --- | --- |
| `target_id` | 内部銘柄主キー |
| `target_key` | 内部互換キー。一意。例: `8697.T`, `TOPIX`, `^VIX` |
| `target_name` | 銘柄・指数名 |
| `target_type` | `individual_stock` / `etf` / `mutual_fund` / `reit` / `bond` / `index` / `commodity` |
| `market` | 市場・取引所 |
| `currency` | ISO 4217通貨コードを推奨。例: `JPY`, `USD` |
| `is_active` | 有効フラグ |
| `created_at`, `updated_at` | 作成・更新日時 |

## 5. データ取得・外部識別子

### `data_source`

| 列 | 定義 |
| --- | --- |
| `source_id` | 主キー |
| `source_key` | 取得元キー。一意。例: `jquants`, `fred`, `yfinance` |
| `source_name` | 表示名 |
| `base_url` | APIベースURL |
| `terms_url` | 利用条件・規約URL |
| `is_active` | 利用中フラグ |
| `created_at`, `updated_at` | 作成・更新日時 |

### `ingestion_run`

| 列 | 定義 |
| --- | --- |
| `ingestion_run_id` | 実行ID |
| `job_type` | パイプライン種別と契約バージョン。例: `jquants_market_prices_archive_v1`, `jquants_financial_archive_v1` |
| `git_commit_sha` | 実行した取得・変換・検証コードのGitコミットSHA。Git外や開発中の実行では `NULL` 可 |
| `source_id` | 取得元 |
| `status` | `running` / `succeeded` / `partial` / `failed` |
| `requested_from`, `requested_to` | APIへ要求した対象期間。日付形式を原則とする |
| `target_count` | 対象件数。0以上 |
| `fetched_count` | 取得件数。0以上 |
| `loaded_count` | DB反映件数。0以上 |
| `skipped_count` | 除外・変更なし件数。0以上 |
| `failed_count` | 失敗件数。0以上 |
| `raw_path` | rawレスポンスの保存先。リポジトリ基準の相対パスを推奨 |
| `error_message` | 実行全体の代表エラー |
| `started_at` | 開始日時 |
| `finished_at` | 終了日時。実行中は `NULL` |

現行MVPでは専用の変換バージョンテーブルを設けません。`job_type`でパイプラインとデータ契約の種類を識別し、`git_commit_sha`で実際に使われた取得・変換・検証コードを特定します。これに `started_at`、`raw_path`、各レコードの `source_record_hash` を組み合わせて加工来歴を追跡します。

### `ingestion_error`

| 列 | 定義 |
| --- | --- |
| `error_id` | 主キー |
| `ingestion_run_id` | エラーが発生した実行 |
| `entity_type` | 対象種別。例: `investment_target`, `date`, `disclosure` |
| `entity_key` | 失敗対象を再特定できるキー |
| `stage` | 発生工程。例: `fetch`, `normalize`, `validate`, `load` |
| `error_type` | 例外・エラー分類 |
| `error_message` | エラー内容。認証情報やレスポンス全文は保存しない |
| `retryable` | 再試行可能なら `1` |
| `created_at` | 記録日時 |

### `investment_target_identifier`

| 列 | 定義 |
| --- | --- |
| `investment_target_identifier_id` | 主キー |
| `target_id` | 内部銘柄 |
| `source_id` | 識別子を使用する取得元 |
| `identifier_type` | 識別子種別。例: `jpx_code`, `ticker`, `fred_series_id` |
| `identifier` | 取得元で使う値。J-Quantsなら5桁 `Code` |
| `valid_from` | 有効開始日。不明時は `0001-01-01` |
| `valid_to` | 有効終了日。現行なら `NULL` |
| `is_primary` | 同一取得元で優先する識別子なら `1` |
| `created_at`, `updated_at` | 作成・更新日時 |

一意キーは `(source_id, identifier_type, identifier, valid_from)`。同じ外部識別子の期間履歴を保持し、`valid_to >= valid_from` とします。

## 9. 削除・履歴保持方針

- マスタは原則物理削除せず、`is_active = FALSE` にします。
- 時系列、取込履歴、財務開示は再現性確保のため履歴を保持します。
- その他の外部キーには自動削除を設定していません。参照中の親レコード削除は失敗させます。
- rawデータ本体はDB外に保存し、`ingestion_run.raw_path` から追跡します。
