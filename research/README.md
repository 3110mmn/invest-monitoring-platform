# Research

DuckDB + Notebookで横断・時系列の探索分析を行う領域です。ここで得た候補や結論を、そのままAPI、
Assessment、Decisionへ保存しません。継続監視する価値が確認できた項目だけを後続実装へ昇格させます。

## EDINET DB Source Qualification

過去財務を全社backfillする前に、EDINET DB APIが分析に必要な期間・科目・来歴を持つかを
小売20社で実測します。APIレスポンス、集計CSV、レポートは利用条件と実データ保護のため
`research/outputs/edinetdb_source_qualification/`へ保存し、Git管理しません。

```bash
export EDINETDB_API_KEY='...'
python -m research.edinetdb_source_qualification \
  --industry retail \
  --sample-size 20 \
  --jquants-parquet data/parquet
```

無料枠は100リクエスト/日です。既定の20社では企業一覧、年次財務、セグメントで約41件を
使用します。取得済みresponseはローカルキャッシュから再利用します。API側を取り直す場合だけ
`--refresh`を指定してください。

出力：

- `company_coverage.csv`：企業別の取得年度、連続年数、科目・来歴・セグメント充足状況
- `field_coverage.csv`：科目別の行充足率と採用ゲート
- `full_history_field_coverage.csv`：取得できた全期間の科目別充足率（参考診断）
- `jquants_reconciliation.csv`：年度・銘柄・科目単位のJ-Quants重複値との照合
- `reconciliation_exceptions.csv`：J-Quantsと一致しない値と差異率
- `quality_dimensions.csv`：連結区分・会計基準・来歴の分布
- `missing_field_details.csv`：必須科目欠損の企業・年度・品質属性
- `qualification_summary.json`：機械可読な採否と既知制約
- `report.md`：採用ゲートの要約

採用判定は、80%以上の企業で3年以上連続し、企業ごとの直近10年度について売上高・営業利益
90%以上、売上原価・販管費70%以上を満たすことです。全取得期間の充足率も別途出力し、古い年度の
欠損を隠しません。評価期間は`--qualification-years`で変更できます。NULLを0で補完せず、金融庁原本の完全性と第三者APIの抽出品質を
同一視しません。`/financials`は年度ごとの採択値であり、訂正前後の全version確認は別途
金融庁EDINET APIが必要です。

## Retail Sales Nowcast — 最初のClosed-loop Pilot

業界統計から企業の月次既存店売上（前年同月比）を予測し、**予測誤差を測り続ける**分析です。

主題は予測精度ではなく**検証可能性**です。株価リターンは仮説の成否を生涯に数回しか
確かめられませんが、月次売上は30日で答えが出ます。年12周回せることが、この題材を選んだ
理由です。

### 入力

列構成は`*.example.csv`を参照してください。`month`は`YYYY-MM`、`yoy_pct`は前年同月比を
%で表した実数、`retrieved_as_of`はその値を取得した日付です。

1. **業界統計** → `research/inputs/industry_monthly_sales.csv`
   [e-Stat](https://www.e-stat.go.jp/)の商業動態統計（経済産業省）から、対象企業の業態に
   対応する小売業の月次前年比をCSVでダウンロードして整形します。
2. **企業の月次売上** → `research/inputs/company_monthly_sales.csv`
   対象企業のIRが公表する月次売上高（既存店前年同月比）を転記します。

**`retrieved_as_of`を必ず入れてください。** 商業動態統計は速報から確報へ改訂されます。
改訂後の値で過去を再学習すると、当時は見えなかった数字で判断したことになります。月を
追記していくたびに、その行の取得日を入れてください。

e-Stat APIは無料のアプリケーションID登録が必要です。現状は手動配置で足りるため使って
いません。経済産業省のサイトは機械的な取得を拒否するため、e-Statから取得します。

### 実行

```bash
python -m pip install -r backend/requirements-research.txt
python -m research.retail_sales_nowcast
python -m research.retail_sales_nowcast --lag 0   # 同月の統計が使える前提で比較する
```

結果はGit管理外の`research/outputs/retail_sales_nowcast/`へ、月ごとの予測と要約CSVとして
保存します。

### 設計上の約束

- **先読みをしない。** 月tの予測は月t未満の情報だけで作ります（expanding window
  out-of-sample）。将来の月を追記しても過去の予測が変わらないことをテストで検証しています。
- **判定は切片だけのモデル（過去平均）との比で行う。** 業界統計が情報を足しているかを
  測るには、同じ窓・同じ手順の入れ子モデルと比べる必要があります。
- **前月横置き（random walk）を判定基準に使わない。** 前年比系列は自己相関が弱く、前月横置きは
  過去平均より√2倍ほど誤差が大きいため、業界統計が完全に無関係でもMAE比が0.71前後になり
  「改善した」と誤って報告されます。合成データで再現したうえで、参考値としてのみ出力します。
- **既定のラグは1か月。** 企業の月次開示は月末から数日後、商業動態統計の速報は約4週後なので、
  企業が月tを開示する時点で業界統計の月tは存在しません。この非対称性は、企業の月次売上が
  業界統計の先行指標になり得ることも意味します。

### 解釈上の制約

- 単一企業・単変量の関連であり、因果ではありません。景気、天候、価格改定、新規出店を統制しません。
- 業界統計の業態区分は企業の売上構成と一致しません。店舗構成・地域構成・カテゴリ構成の
  違いは残ります。この対応づけは手作業の判断であり、分析の本体です。
- 既存店前年比の定義（対象店舗の算入基準、改装中の扱い）は企業ごとに違います。横断比較しません。

## Breach Event Study — 結論は「ほぼ何も言えない」

個人情報漏洩の公表後に株価がどう動いたかを、市場モデルの異常リターンで記述します。

**この分析は失敗しています。記録として残しています。** 失敗の内容は下記「測定した結果」の
とおりで、コード自体は動作し再利用できます。

### 入力

`breach_events.example.csv`を`breach_events.csv`へコピーして記入します（列の意味は
`research/inputs/README.md`）。価格はyfinanceから取得します。

### 実行

```bash
python -m pip install -r backend/requirements-research.txt
python -m research.breach_event_study
python -m research.breach_event_study --benchmark 1348.T
```

結果はGit管理外の`research/outputs/breach_event_study/`へ、日次パネルとイベント別要約CSVとして
保存します。

### 測定した結果（n=6、2026-10-09時点）

**進行中のイベントはノイズ帯が日々広がります。** 帯は√経過日数で伸びるため、イベント直後に
「帯を超えた」と見えても、日が経つと帯の内側へ入ることがあります。下表は2026-10-09の
実行値で、`latest_day`が20営業日に達していない4件は暫定です。

**6件中5件で決定係数が0.2未満でした。** 市場モデルが株価変動の1〜14%しか説明しておらず、
「異常リターン」の大半は市場で説明できない個別要因です。その中に漏洩の影響が含まれるのか、
他の材料なのかを区別できません。

さらに、累積異常リターンを推定窓の残差標準偏差（×√経過日数）と比べると、**明確に
ノイズ帯を超えたのは2件だけ**でした。

| 企業 | 独立性 | R² | 底のCAR | ノイズ帯(1σ) | 経過 | 判定 |
|---|---|---:|---:|---:|---:|---|
| 大和証券グループ本社 | `third_party` | 0.57 | −7.1% | ±2.2% | 2日 | 超過 |
| パーク24 | `independent` | 0.14 | −13.3% | ±7.0% | 9日 | 超過（R²低い） |
| 物語コーポレーション | `independent` | 0.07 | −5.7% | ±5.4% | 4日 | 境界 |
| イエローハット | `independent` | 0.11 | −9.7% | ±10.9% | 60日 | **ノイズ帯の内側** |
| KDDI | `contaminated` | 0.01 | −0.1% | ±11.2% | 60日 | ノイズ帯の内側 |
| さくらインターネット | `follow_up` | 0.09 | +2.3% | ±15.6% | 18日 | ノイズ帯の内側 |

**R²とノイズ帯を出す前は「独立3件はすべて下落し、1〜7営業日目に底を打つ」と読んでいました。**
イエローハットの−9.7%は平常時の変動と区別できず、この読みは成立しません。説明力の無い
モデルの残差を効果と誤読する典型です。したがって`market_model`はR²と残差標準偏差を常に
返し、R²が0.2未満のイベントがあれば標準エラーへ警告します。

日本の個別株とTOPIXの日次相関は0.3〜0.44（R²で0.09〜0.19）であり、**この低いR²は異常では
なく正常**です。個別株は市場要因より個別要因で動きます。市場モデルをセクターモデルへ
替えるか週次へ落とせばR²は上がりますが、**n=6という制約は解消しません。**

### 解釈上の制約

- **n=6。統計的な一般化はできません。** 平均CARの信頼区間も「底は平均N営業日」も主張しません。
  出力は「この6件ではこう動いた」という事例集です。
- ノイズ帯は検定ではなく桁感です。残差の独立性を仮定しており、イベント期の分散拡大を
  考慮していません。
- 独立性の3件（`contaminated` / `follow_up` / `third_party`）を平均へ混ぜません。群別に表示します。
- 公表日が非営業日の場合は直後の営業日を起点にします。
- 漏洩以外の同時期の材料（決算、ガイダンス修正、指数の入れ替え）を統制していません。
  R²が低い以上、これらが残差へ入っています。

### ベンチマークの既定を1348.Tにしている理由

**`1306.T`は使えません。** 2024年の分割が`Adj Close`へ反映されておらず、日次リターンの
標準偏差が0.433、最大+947%という値になります。これをベンチマークにするとβがほぼ0へ潰れ、
異常リターンが「個別銘柄の生リターン」になります。`1321.T`も同様でした。

黙って通すと結果が壊れたまま出るため、`fetch_prices`は日次標準偏差が5%を超える系列で
例外を投げます。

## 会社予想の精度 — point-in-timeの検証

会社が出す通期営業利益予想が、実績からどれだけ外れるかを記述します。計算定義は
`backend/analytics/derived/point_in_time_forecast.sql` と `forecast_accuracy.sql`で、
Research専用スクリプトではなくDerivedとして置いています。

### なぜ「予想をどれにするか」が分析の本体か

会社は期中に何度も通期予想を出し直します。実測では(企業×年度×期)の1,047グループで
複数回の開示があり、最大5回でした。実例としてコード18210の2025年3月期は、通期営業利益
予想を10億→25億→75億と修正しています。

**最後の予想を「会社予想」として実績と比べると、MAPEが28.7%から17.0%へ下がりました。**
4割の精度向上に見えますが、期末直前の修正を使っているだけで全て後知恵です。単純なJOINを
書くとこの数字が黙って出ます。

したがって`point_in_time_forecast`は予想を畳まず、各予想に有効期間（`as_of_date`〜
`superseded_at`）を与えます。「最新」は基準日に依存するので、ROW_NUMBERで最新を取る
実装にはしません。

### 測定した結果（n=19,860、2026-10-09時点）

期初予想（`forecast_seq = 1`）と期中修正後を、売上高でスケールした誤差で比べました。

| | 件数 | 中央値 | 90パーセンタイル |
|---|---:|---:|---:|
| 期初予想 | 5,961 | 1.12% | 5.25% |
| 期中以降 | 13,899 | 0.75% | 3.66% |

期初予想の着地は、**57.8%が上振れ、42.0%が下振れ**でした。Parquetから直接数えた
別経路の測定（62.4%が会社予想を上回る）とも整合しており、独立した検算になっています。

### MAPEを使わない理由

実績営業利益を分母にすると、着地がゼロ近傍の企業で誤差が発散します。実測では中央値16.8%に
対して**最大70,800%**で、750件が100%を超えました。最悪の例は予想7.09億円に対して実績
100万円です。分母が小さいだけの行が平均を支配します。

代わりに売上高でスケールし、「売上の何%にあたる利益の読み違いか」として読みます。

### 上振れ・下振れは翌年へ持続するか（n=2,685）

前年の着地が翌年の方向に情報を持つかを測りました。**判定基準は測定前に決めています**
（業種内で+5ポイント以上かつ有意なら弱い証拠として記録、下回れば棄却）。

**ベースラインを置いて比べます。** 全体の59.4%が上振れするので、「前年上振れ組の70.9%が
翌年も上振れた」をそのまま持続性と読むと、既知の事実を言い換えるだけになります。

| | 翌年に上振れ |
|---|---:|
| ベースライン（前年と無関係） | 59.4% |
| 前年上振れ組 | 70.9% |
| **差** | **+11.5ポイント** |

オッズ比3.14、カイ二乗200.5、p=1.6e-45。2×2は`[[1097, 450], [497, 641]]`です。

**業種要因ではありません。** 「その業種が2年とも好調だった」だけなら銘柄選択の根拠にならない
ため、業種（`sector_33`）×年度で層別して取り直しました。

| | 差 |
|---|---:|
| 全体 | +11.5pt |
| 業種×年度内（加重平均、25セル） | **+10.8pt** |

25セル中24セルで正の方向でした。2つの遷移（2024→2025、2025→2026）でも同じ向きで、
下振れ組も対称に持続しています（翌年の上振れが41.1%・44.5%とベースラインを下回る）。

### 持続性について言えないこと

- **3年連続の検証はできません。** 3年とも観測できる企業が1社しかなく、「2年連続で上振れた
  企業は3年目も上振れるか」は測れていません。
- **2つの遷移はどちらも2024〜2026年です。** 同一局面であり、景気循環をまたいでいません。
  この結果が一般的な性質か、この期間固有かを区別できません。
- **因果を特定していません。** 上振れが続く理由が「経営の保守性」なのか「たまたま成長局面の
  企業群」なのかを分離していません。前者なら続き、後者なら局面が変われば消えます。
- 3年とも開示がある企業だけを見ており、上場廃止・決算期変更による脱落を補正していません。
- 業種は現在時点の分類を過去へ適用しています。`sector_33`が引けない83件を含みます。

### 解釈上の制約

- **年度は3つ（2024・2025・2026年度）。** J-Quants Freeプランの2年窓によるもので、景気局面を
  またいだ検証はできません。2024年度は711件と少なく、遷移ペアは2組です。
- **12週遅延。** 過去の検証はできますが、リアルタイム運用には使えません。
- **銀行は対象外。** 営業利益を開示しないため（実測で銀行7社19開示のうち営業利益は0件）、
  結果として行が作られません。
- 会計基準・連結範囲が揃わない組み合わせは比較せず、`comparison_status`で理由を返します。
  実測では287件が`accounting_standard_mismatch`でした。
- 実績の訂正開示は採点に使いません。最初に出た実績で評価します。

## REIT Rate Sensitivity Pilot

用途分類別に、J-REITの週次**Total Return**と10年JGB利回り変化の関係を探索します。価格はyfinanceから
取得してローカルへキャッシュし、用途分類と財務省の金利CSVもローカル入力として扱います。BigQuery、
Snowflake、dbt、Airflow、API、PostgreSQL、GCSへの新しい保存先は追加しません。

### 入力

1. `research/inputs/reit_asset_types.example.csv`を`reit_asset_types.csv`へコピーして、手元で対象REITを分類します。
   `asset_type`は`office`、`retail`、`residential`、`logistics`、`hotel`、`healthcare`、`diversified`、
   `composite`、`other`のいずれか。
   出典上の分類名は`source_label`に原表記で残し、分析用の統一分類と区別します。
2. [財務省の過去の国債金利情報](https://www.mof.go.jp/english/policy/jgbs/reference/interest_rate/historical/)から
   `jgbcme_all.csv`をダウンロードし、`research/inputs/`へ置きます。
3. 分類元・基準日・URLを分類CSVの各行に記録します。Japan-REIT.comを使う場合は利用条件を確認し、
   自動収集や分類データの公開・第三者提供は行いません。

入力ファイルは`.gitignore`対象です。公開リポジトリに分類データ、金利CSV、生成結果は含めません。

### 実行

```bash
python -m pip install -r backend/requirements-research.txt
python -m research.reit_rate_sensitivity            # 価格キャッシュを使う
python -m research.reit_rate_sensitivity --refresh   # yfinanceから取り直す
```

価格は`research/inputs/reit_prices_yfinance.csv`へキャッシュします。既定ではキャッシュを使い、
`--refresh`のときだけ取得します。58銘柄の全期間取得は非公式エンドポイントへ58リクエストを
送るため、分析条件を変えるたびに取り直しません。調整値は遡及して変わるので`fetched_at`を
キャッシュに残します。結果はGit管理外の`research/outputs/reit_rate_sensitivity/`へ
週次パネルと用途別要約CSVとして保存します。

### 価格の取得元にyfinanceを使う理由

Parquet lakeはJ-Quants Freeプランの2年窓しか持たず、週次に落とすと106点しか残らないため
用途分類別の感応度を検定できませんでした。yfinanceは58銘柄すべてで2005年まで遡り（48銘柄が
10年以上）、`Adj Close`が分配金再投資を織り込むのでTotal Returnが作れます。分配金イベントは
58銘柄で計1,707件ありました。

**ただしこれはResearch限定の判断です。** yfinanceの調整値は遡及して変わり、`ingestion_run`に
来歴も残らないため、一次観測の取得元としてはJ-Quantsに劣ります。
この分析はワンショットで、プラットフォームのETLには入れません。

### 解釈上の制約

- `Adj Close`から計算する**Total Return**です。分配金を含まない価格リターンも併記し、
  インカムの寄与が見えるようにしています。
- yfinanceの長期履歴には単発の壊れた価格が混じります。前後5営業日の中位値から5倍以上
  乖離する終値を除外し、除外した行は標準エラーへ報告します。2026-10-07時点では
  8951.Tの2007-07-06（終値2,690円、前後は175,000円前後）の1件だけでした。
  2008年や2020年の30〜45%下落は実際の市場の動きなので残ります。
- 現在時点の用途分類を過去へ適用する探索です。分類変更、上場廃止銘柄の欠落によるsurvivorship biasを解消しません。
  **21年の窓では影響が大きくなります。** 生存している58銘柄だけを見ており、途中で消えた銘柄は入りません。
- 出力される金利係数は同時点の単変量関連を表し、因果効果ではありません。景気、インフレ、市場全体等を統制しません。
- グループ別のHAC信頼区間は初期探索用で、グループ間係数差の正式な検定ではありません。
